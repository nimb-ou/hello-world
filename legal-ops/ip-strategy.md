## 3. Patents

### 3.1 Patentability context (be realistic)
- Location-based audio guides, geofenced narration and AR "look left" cues have **extensive prior art** (museum audio guides, Google Maps Live View, Apple Maps, BlindSquare, Soundscape (Microsoft), Bose AR, Detour app, VoiceMap). Claims must be **narrow and technical**: specific sensor-fusion steps, confidence thresholds and data structures, not "telling stories about buildings".
- **US law (Alice / §101)**: claims must be tied to concrete technical improvements (e.g., improved heading accuracy without a camera; reduced power; reduced false triggers), not abstract ideas.
- **EPO**: the "technical character" test. Sensor fusion and power saving are good; "choosing which story to tell" is weaker.
- **Absolute novelty** in the EU/China/Japan/India: **any public disclosure before filing kills foreign patent rights.** The US has a 1-year grace period, but don't rely on it. **No Kickstarter video, demo day, blog, academic paper or open-source push of Map Vision code before a provisional is filed.**

## 5. Open-source, open-data and model licence compliance

### 5.1 OpenStreetMap: ODbL 1.0
- **Produced works** (rendered maps, audio narration that mentions a street name, routing directions) need **attribution** when used publicly: "© OpenStreetMap contributors", with a statement/link that the data is under the **ODbL**. It must be visible without user interaction where practical (e.g., on the map view; on the screenless Pebble, in the app + "About/Credits" + packaging/manual + spoken credits in an "About" voice command) ([OSMF Attribution Guideline, adopted 25 Jun 2021](https://osmfoundation.org/wiki/Attribution)).
- **Derivative databases** (our cleaned/enriched OSM extracts in City Packs) that we **distribute publicly** (City Packs are distributed to devices) trigger **share-alike**. We must offer the **derivative database** (or a diff/method) under ODbL. Under the OSMF guideline, **training datasets built from substantial OSM extracts count as derivative databases** if publicly used.
- **Design rule:**
  1. Keep **OSM-derived layers** (geometry, POI tags, routing graph) as a separable ODbL database; publish them (e.g., downloadable on a "Data" page or on request).
  2. Keep **LORE story units** (our text/audio, licensed guide content) in a **separate, independent database** that references OSM IDs only as **keys**. This is a "collective database" under ODbL §4.5(b): not a derivative, so no share-alike. Counsel to confirm.
  3. Don't mix proprietary geometry corrections back into the OSM layer without publishing them. Better: **contribute corrections upstream to OSM**, which is good community relations.
  4. If we use third-party map tiles/geocoders (Mapbox, MapTiler, Stadia, HERE), follow their own attribution rules.

### 5.2 Wikipedia / Wikimedia: CC BY-SA 4.0 (text), various (images)
- Text since mid-2023 is **CC BY-SA 4.0** (older revisions dual-licensed CC BY-SA 3.0 + GFDL).
- If a story **reuses or adapts** Wikipedia text (including close paraphrase or machine summarisation that keeps protected expression), the **adapted text must be licensed under CC BY-SA** and attributed (title, link, authors via history link, licence, and an indication of changes).
- **Facts themselves are not copyrightable.** Our editorial policy: **use Wikipedia/Wikidata as a fact source; write original narration** (or have the LLM generate from structured facts, then edit); keep a citation. This keeps narration proprietary while staying compliant. Wikidata is **CC0**, with no attribution required, but we credit it anyway.
- **Images** on Wikimedia Commons each have their own licence (CC BY, CC BY-SA, PD, some non-free). Record each image's licence in the content DB.
- **The share-alike "infection" risk:** if LLM-generated stories are trained or fine-tuned on Wikipedia text, outputs are generally not considered adaptations, but **verbatim regurgitation** would be. Run n-gram overlap checks against source passages (e.g., flag >50-character verbatim spans) and require attribution or a rewrite.
- Spoken attribution format: *"Sources include Wikipedia, licensed CC BY-SA."* plus a full credits page in the app with links.

### 5.5 Software open-source compliance
- **SBOM** (SPDX or CycloneDX) generated in CI for firmware, app and backend; licence scanning (e.g., FOSSA, Snyk, ScanCode, `license-checker`).
- **Policy:**
  - Allowed: MIT, BSD, Apache-2.0, ISC, Zlib, MPL-2.0 (file-level), LGPL (dynamic link only; give users the ability to relink).
  - Review needed: GPL-2.0/3.0, AGPL (never in backend services without approval), EPL, CC-BY-NC, SSPL, BUSL, "Commons Clause".
  - **Device OS:** if Linux/Android-based, the **GPL kernel** source (including our kernel patches) must be offered via a **written offer valid for 3 years** (GPLv2 §3(b)). **GPLv3 "installation information"** (anti-tivoisation) applies to user products: avoid GPLv3 components in locked-bootloader firmware, or provide installation info. If Zephyr/FreeRTOS (Apache-2.0/MIT), it's simpler.
  - Keep **CRA** obligations in mind (SBOM, vulnerability handling). See `compliance-matrix.md`.
